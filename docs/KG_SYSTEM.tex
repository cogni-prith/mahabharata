\begin{abstract}
\noindent
This document records what the system is built from and what it does, at the
level of detail needed to reproduce or to audit it. Every figure quoted here
was read from the artifacts on disk at the date above, not from memory.

The deliverable is a trained knowledge graph embedding over a
citation-anchored symbolic graph extracted from an annotated English
translation of the BORI critical edition. The symbolic graph is training data,
not the product.

Two statements govern how the rest should be read. The Phase~6 entry gate fails
on all three of its conditions and the model was trained anyway on explicit
instruction, so no metric in Section~\ref{sec:embedding} is a finding about the
Mahabharata. Entity resolution is unfinished: all 121 appellations remain
unresolved and nothing is merged. Both facts are repeated wherever they bear on
a number.
\end{abstract}

\section{Design rules}

Five rules constrain every component. They are not style preferences; each one
exists because violating it produced a specific wrong output that was found and
corrected.

\begin{enumerate}
\item \textbf{Never invent a citation.} A triple with no supporting span is
marked \pred{uncited} and stays visible as such. Fabricated provenance is worse
than absent provenance because it cannot be detected downstream.

\item \textbf{Never guess an entity link.} Where a referent is genuinely
ambiguous the system emits a candidate set with confidences, never a single
silent choice. ``Achyuta'' has five candidates and the best scores 0.25.

\item \textbf{Leave contested facts unasserted.} Abhimanyu has no single
recorded slayer, so no edge is emitted and a note records why.

\item \textbf{Predicted triples never enter the asserted graph.} Embedding
output is a hypothesis. It lives in a separate named graph, always carries a
score, and is labelled \pred{predicted} in every view.

\item \textbf{Identity is a relation, never \pred{owl:sameAs}.} \pred{isAmshaOf},
\pred{rebornAs}, \pred{transformedInto} and \pred{disguisedAs} stay strictly
separate. A shared name is not a resolved person.
\end{enumerate}

\subsection{Measured properties that govern the design}

\begin{itemize}
\item \textbf{Eight parvas have a human pass, not twelve.} Two of the eight are
unrevised machine output: Mahaprasthanika is byte-identical to the LLM file and
Mausala differs by one token.

\item \textbf{The human pass changed 1.25\% of tokens}, 4{,}780 of 382{,}001.
The human layer is therefore not independent of the LLM layer, which is why
Phase~5 cannot verify LLM proposals against it.

\item \textbf{The \pred{gold_hand} tier in the master CSV is mislabelled.} Its
parvas are Sabha, Virata and Stri, none of which has a human file. It is never
used for a score.

\item \textbf{No shloka number is printed inline anywhere.} The citation unit is
therefore \pred{(parvan, adhyaya)} and shloka-level citation is impossible from
this corpus.

\item \textbf{\file{shanti_parva.csv} is not confined to Shanti Parva.} It
shares 1{,}635 long sentences with \file{anushasana_tagged.csv} and ends with
Mahaprasthanika text, so its parva labels are re-derived rather than believed.
\end{itemize}

\subsection{The substrate join}

The master CSVs carry punctuation and quotes; the BIO CSVs carry token spans.
Joining them is mandatory and the obvious key is wrong.

\textbf{The join is on normalised sentence text}: strip possessives, replace
punctuation with whitespace, drop digit-only tokens, collapse whitespace,
lowercase. Measured coverage is 95.1\% to the LLM files and 95.7\% to the human
files, with no parva below 89.3\%.

\textbf{The index join must not be used.} Joining on
\pred{sent_id + 1 == sentence_no} scores roughly 96\% on fourteen parvas and
\emph{exactly 0\%} on Karna, Shalya, Mahaprasthanika and Svargarohana, dropping
four entire parvas silently as absent rows rather than as errors. The master CSV
is a sparse subset that kept its original indices while the BIO files
re-segmented independently. No fixed offset repairs it, and a five-parva sample
does not reveal it.

\subsection{Chapter head recovery}

Three head formats occur in the extracted PDF stream and all three are handled:
\pred{CHAPTER 1162(45)} (1{,}162 heads), a bare \pred{226(1)} with the word
omitted (608), and in Adi a bare global number on its own line, detected from
layout at 10.8\,pt against a 14.4\,pt body (224, plus 1 fused).

\subsection{Two anchoring decisions}

\textbf{Mentions anchor on the sentence midpoint, not its start.} Drop caps
place the decorative initial before the chapter head in the extracted stream, so
a first-sentence-of-chapter reads \pred{' 'S Chapter 1152(2) anjaya said} and
begins before the boundary it belongs after. Start-anchoring placed every such
sentence one chapter early, which was all of Karna and all of Shalya.

\textbf{Anchors are keyed on \pred{(parva, ordinal)}, never on the printed
number.} Printed global chapter numbers contain typos in the source, confirmed
in Shalya, which prints \pred{Chapter 1126(7)} where the sequence requires 1226.
The printed number is retained as an observed attribute only.

\section{Phase 2: entity resolution}
\label{sec:phase2}

\textbf{This phase is construction, not validation, and it is not finished.}

\subsection{Why the supplied prior cannot be used as truth}

\file{build/canonical_id_audit.md} measures the corpus \pred{canonical_id}
prior. It is a context-free dictionary: every surface form has exactly one
value, applied regardless of context. Of 3{,}958 distinct values, only 16 carry
more than one surface form, and 88.0\% of assignments are verbatim echoes of the
surface. It performs 43 distinct rewrites covering 11{,}624 mentions.

The failure mode is automated canonicalisation collapsing a patronymic epithet
onto its bearer. The Bharadvaja to Drona collapse covers 295 rows and the
Krishna Dvaipayana to Krishna collapse 72 rows. These are not one-off bugs and
the quantification of this failure is itself a reportable result.

\subsection{The appellation algorithm}

\begin{enumerate}
\item \textbf{Candidate names}: single-token PERSON surfaces with at least 10
mentions, minus a title stoplist, matching
\begin{center}\small\verb|[A-Z][a-z]{2,}|\end{center}

\item \textbf{Apposition mining}: adjacent capitalised pairs such as
``Vaikartana Karna'' are found by
\begin{center}\small\verb|\b([A-Z][a-z]{2,})\s+([A-Z][a-z]{2,})\b|\end{center}

\item \textbf{Direction}: the member with the lower bare-mention count is taken
as the epithet, the other as the bearer.

\item \textbf{Homonym risk}: heads that would absorb epithets promiscuously are
blocked.

\item \textbf{Resolution thresholds}: a merge requires at least 3 sightings, a
share of at least 0.90, and a runner-up below 0.10, \emph{and} agreement with
the corpus prior.
\end{enumerate}

\section{Phase 4: relation extraction}
\label{sec:phase4}

\subsection{Method}

English dependency parsing over the translated prose. Each sentence is parsed,
and hand-written patterns read subject, verb and object off the dependency tree.
That the corpus is pure English is an advantage here rather than a loss:
Sanskrit dependency parsing is thin and would have been the hardest part of the
project.

The caveat this incurs is recorded and belongs in any write-up: \emph{every
relation in this graph is mediated by one translator's word choices.}

\subsection{Guards, and why each exists}

Each guard was written after a specific wrong triple was traced to its evidence.

\begin{itemize}
\item \textbf{Possessed kinship nouns.} When a clause argument is ``X's son'' or
``his brother'' the referent is a description, not a name. Resolving it to a
single antecedent is the silent choice the rules forbid. This guard emptied
\pred{(Abhimanyu, slainBy, *)}, which was the one fact the project names as
contested. The extractor dropped from 3{,}060 rows to 2{,}935.

\item \textbf{Coreference arguments on conflict predicates.} \pred{slainBy},
\pred{foughtWith} and \pred{defeatedBy} refuse any argument recovered by
coreference. Unverified antecedents had turned ``him'' into Adhiratha and ``the
Pandava'' into Pandu.

\item \textbf{Death verbs must be literal.} ``Destroy'' does not establish a
death.

\item \textbf{Apposition across clause boundaries.} A role phrase at a new
clause boundary cannot inherit the previous clause's object as its bearer.
\end{itemize}

\subsection{The review pass}

\file{src/review_viewer_graph.py} re-runs every record through the current
guards, because the raw extractor output predates several of them. It writes
\file{build/reviewed_relations.parquet} (1{,}774 asserted) and
\file{build/withheld_relations.parquet} (1{,}145 withheld).

\textbf{Withheld is not disproved.} The withheld set contains true statements.
\pred{(Duryodhana, slainBy, Bhimasena)} is withheld from ``He has been slain by
Bhimasena, with an upraised club'', because the subject is a pronoun resolved by
coreference. \pred{(Karna, slainBy, Nakula)} is withheld from the identical
shape and is false. No guard can distinguish them from the sentence alone, so
applying the rule consistently costs the true one. Recall on \pred{slainBy}
falls from 125 rows to 53 and on \pred{foughtWith} from 680 to 229.

\section{Phase 5: propose and verify}

An LLM proposes candidate triples freely. Verification is redesigned because the
annotation layer is contaminated.

\textbf{The annotation is an index, not evidence.} It changed 1.25\% of tokens
against the LLM output, so verifying LLM proposals against it would measure a
model against a lightly edited copy of its own output. The annotation is used
only to retrieve candidate sentences; verification is against the prose.

\textbf{Calibration is on a blind set}, re-annotated from scratch, blind to the
LLM output. The sampling procedure was written before sampling: three strata
over 11{,}550 eligible sentences, seed 20260914, sheet id \pred{59a1d3129190},
419 rows, all 18 parvas represented. Stratum A is 200 allocated by predicate,
stratum B is 200 by parva over sentences the pipeline produced nothing from,
stratum C is a census of all 19 proposal-bearing sentences.

\textbf{Status: blocked.} 26 proposals exist in \file{out/proposed.ttl}, none
asserted. The blind set is unjudged, so no groundedness rate can be reported. A
number computed against the existing human files would be silver-versus-silver
and is never reported as an independent evaluation.

\subsection{Why RotatE and not TransE}

The predicate set contains relations of three algebraic shapes, and the choice
of model is forced by them.

TransE embeds a relation as a translation, $\mathbf{h} + \mathbf{r} \approx
\mathbf{t}$. For a symmetric relation this requires
$\mathbf{h}+\mathbf{r}\approx\mathbf{t}$ and
$\mathbf{t}+\mathbf{r}\approx\mathbf{h}$ simultaneously, which forces
$\mathbf{r}\approx\mathbf{0}$ and therefore $\mathbf{h}\approx\mathbf{t}$. Every
ally collapses onto their ally. TransE cannot represent symmetry at all.

RotatE embeds entities in complex space and each relation as an element-wise
rotation:
\[
\mathbf{t} \approx \mathbf{h} \circ \mathbf{r}, \qquad
|r_i| = 1, \qquad
r_i = e^{\mathrm{i}\theta_i}
\]
with score $f(h,r,t) = -\lVert \mathbf{h}\circ\mathbf{r}-\mathbf{t}\rVert$.
Symmetry is a rotation by $\pi$, since applying it twice returns the original.
Antisymmetry, inversion and composition all follow from the group structure.

\subsection{Determinism}

A seeded run reproduced only to $4\times10^{-7}$, because the gradient scatter
into the embedding reduces in block-completion order. That was enough to move
638 of 683 entities in the UMAP layout and drop the projection's top-10
neighbour overlap against its own rerun to 0.32. The trainer now sets
\begin{center}\small
\pred{CUBLAS_WORKSPACE_CONFIG=:4096:8}\quad and \quad
\pred{torch.use_deterministic_algorithms(True)}
\end{center}
before importing torch. Two full train-then-project cycles at seed 20260917 are
now bit-identical.

\subsection{Leakage controls}

Two standard leaks were blocked, and the check was measured rather than assumed.

\textbf{Symmetric leakage.} If \pred{foughtWith(a,b)} is in train and
\pred{foughtWith(b,a)} in test, the model has seen the answer. Pairs are ordered
canonically and deduplicated \emph{before} the split, not after. 75 of 1{,}444
distinct triples were removed as the same fact written both ways.

\textbf{Inverse leakage.} No inverse relation is materialised and PyKEEN's
\pred{create_inverse_triples} is off. Predicate pairs sharing an entity pair in
opposite order were counted: \pred{speaksTo}/\pred{speaksTo} 198,
\pred{foughtWith}/\pred{speaksTo} 28, \pred{foughtWith}/\pred{slainBy} 19, and a
tail of smaller counts.

\section{Phase 7: projection and interface}

\subsection{UMAP}

UMAP reduces the 400-dimensional entity vectors to 2D and 3D coordinates,
\pred{n_neighbors} 15, \pred{min_dist} 0.1, seed 20260917 recorded in
\file{out/projection.json}. A projection whose seed is not recorded is a
screenshot, not a result.

\subsection{Clustering}

Eight k-means groups over the learned entity vectors, seed 20260917. The eight
colours denote those groups and nothing else. \textbf{They do not identify
factions, families, confidence or UMAP regions.} The independent UMAP projection
determines point positions; k-means determines only colour.

\subsection{Interface}

One static HTML page, no framework and no backend. Scoring runs client side: a
few thousand entities at 400 dimensions ships as roughly 4\,MB of float32
alongside the page and scores with a small matrix multiply in JavaScript. The
graph-model view runs from \pred{file://} with no server and makes no external
request.

\subsection{The three query modes}

\begin{enumerate}
\item \textbf{Nearest neighbours in vector space.} Similarity, not adjacency.
The two differ and the difference is the point. \PASS
\item \textbf{Link prediction.} Scores every candidate tail for an incomplete
triple. Rows are labelled \pred{predicted} and \pred{uncited}. \PASS
\item \textbf{Analogy by vector arithmetic.} $\text{Arjuna}-\text{Kunti}+
\text{Gandhari}$ should land near Duryodhana. \textbf{This does not currently
land.}
\end{enumerate}

\section{Phase 8: divergence analysis}

This is the generalised form of the Karna observation, and the one place the
project tests a claim rather than displaying one.

For every entity, compute the overlap between its top-$k$ graph neighbours and
its top-$k$ embedding neighbours by cosine, then rank entities by lowest
overlap. Graph neighbours are ranked by the number of asserted triples joining
the pair; $k=10$; overlap is the intersection over $k$, or over the degree where
the degree is below $k$.

\textbf{The result is negative and is reported as such.} 683 of 683 entities
scored. Mean overlap 0.028, and 0.081 among the 64 entities of degree $\geq$ 10.
616 of 683 entities tie at exactly zero overlap, so the ranked list orders a
tie. At this graph density the measure does not discriminate.

\section{The question-answering layer}

A retrieval and generation layer over the same artifacts. It asserts nothing and
writes no files.

\subsection{Name correction}

Approximate string matching with \pred{rapidfuzz}, scorer \pred{WRatio},
acceptance threshold 85. ``Arjun'' scores 90 against Arjuna and ``Yudhistira''
91 against Yudhishthira, while unrelated names sit in the fifties.

Two constraints, each from an observed failure:

\begin{itemize}
\item \textbf{Mention floor of 10.} The declared entity set contains annotation
artifacts. \pred{Tell} is a declared PERSON on two mentions and was capturing
the verb in ``tell me about Arjuna''. Ten is the threshold Phase~2 already
applies to its own name list. Names below the floor remain reachable through
passage retrieval, which needs no name.

\item \textbf{Spelling variants are returned, not merged.} A misspelling close
to two spellings returns both, because per Section~\ref{sec:phase2} they are
separate entities and nothing asserts they are one person.
\end{itemize}

\subsection{Grammar}

\textbf{No grammar model is installed.} Gramformer and HappyTransformer were
considered and rejected: a multi-hundred-megabyte model to repair input the
answering model already tolerates. One instruction in the prompt covers it.

\subsection{Hybrid retrieval}

Neither half is sufficient alone, so both run and are merged.

\textbf{Graph half.} 1{,}774 reviewed triples joined on bare label strings, with
no predicate filter. Filtering by a predicate guessed from the question is
precisely why a graph-backed system answers ``I do not know'' to a fact it
holds.

\textbf{Passage half.} \pred{sentence-transformers/multi-qa-MiniLM-L6-cos-v1},
384 dimensions, over 16{,}339 passages of which 11{,}599 carry a chapter anchor,
and 6{,}921 typed nodes. Dense cosine is fused with SQLite FTS5 \pred{bm25}
lexical ranking by reciprocal rank fusion:
\[
\mathrm{RRF}(d) = \sum_{r \in R} \frac{1}{k + \mathrm{rank}_r(d)}, \qquad k = 60
\]
so a document ranked moderately by both signals outranks one ranked first by
only one. The encoder runs locally; the model revision, file hashes, input index
hash and UMAP seed 20260916 are recorded in
\file{build/semantic/manifest.json}, and the index refuses to serve if any hash
mismatches.

\subsection{Evidence weighting and budget}

\begin{itemize}
\item \textbf{Support.} Duplicate triples are collapsed and the count of
distinct places stating them is retained. The corpus states
\pred{(Karna, slainBy, Arjuna)} in two chapters and a rival in one; before
support existed the two rendered as equals.

\item \textbf{Per-predicate rotation.} \pred{speaksTo} is 70\% of the reviewed
rows. Ranking by confidence filled the entire context with dialogue while
\pred{slainBy} fell below the cut, so each predicate takes a turn.

\item \textbf{Question-aware ordering.} Words in the question map to predicates,
which take the first half of the fact budget. This orders and never filters.
Instructing the model alone was insufficient: told to lead with parentage it
still answered ``no father is recorded'' with six \pred{bornTo} rows further
down its context.

\item \textbf{Epithet expansion.} A resolved entity also retrieves records filed
under its appellations. This is necessary because the corpus files
\pred{(Dhananjaya, bornTo, Pandu)} six times and
\pred{(Arjuna, bornTo, Pandu)} zero times. Every such record arrives
\pred{resolved: false} and tagged with the name it was recorded under.
\end{itemize}

\subsection{Generation}

\pred{openai/gpt-oss-120b} via the Groq API, selected by reading
\pred{/v1/models} rather than assuming. \pred{groq/compound} is deliberately
avoided because it carries its own web search, and a grounded answer must not
have a route back to the open internet.

The call is opt-in behind \pred{GROQ_API_KEY}. Without a key the layer returns
the retrieved evidence and generates nothing. Only the question and the
retrieved context are transmitted, never the corpus in bulk. Browser-supplied
conversation history is validated rather than repaired, and answer text is
escaped before a small Markdown subset renders it, so the only tags in a
rendered answer are those the renderer writes.

\subsection{Validation}

every Turtle file parses, no proposal appears in the asserted graph, every

\section{Known limits}

\begin{enumerate}
\item \textbf{The Phase 6 gate fails on all three conditions.} Every metric in
Section~\ref{sec:embedding} describes a below-gate fit.

\item \textbf{Entity resolution is unfinished.} 121 appellations unresolved, 0
merged. The gate is a human census that remains unjudged.

\item \textbf{Phase 5 groundedness cannot be reported.} The 419-row blind
calibration set is drawn and frozen but unjudged.

\item \textbf{Phase 8 produced a negative result.} 616 of 683 entities tie at
zero overlap.

\item \textbf{The analogy query mode does not land.}

\item \textbf{Recall was traded for precision in the review pass.} 1{,}145
withheld rows include true statements; withheld is not disproved.

\item \textbf{Every relation is mediated by one translator's word choices.}

\item \textbf{Two training runs are present on disk.} \file{out/eval.md} and
\file{out/embedding_index.json} report 561 entities, 1{,}444 triples and MRR
0.1750, while \file{build/divergence.md} and \file{docs/STATUS.md} report 683
entities, 1{,}771 triples and MRR 0.1453. This document quotes the former. The
two should be reconciled by rerunning the chain end to end, and until then
neither set should be published as final.

\item \textbf{One validation check currently fails.}
\pred{(Ghatotkacha, bornTo, Hidimba)} appears in both the asserted and proposed
graphs, so \file{src/validate_outputs.py} reports 24 of 25.
\end{enumerate}
